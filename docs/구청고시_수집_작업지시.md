# 작업 지시서: 구청 고시로 재개발 사업 단계 최신화

이 문서는 **사용자 PC(한국 IP, 브라우저 사용 가능)에서 실행하는 Claude Code 세션**이 읽고 수행하는 지시서다.
클라우드 세션은 한국 공공기관·재개발닷컴 사이트에 접속하지 못해(연결 차단·403) 이 작업을 하지 못했다.

## 1. 배경과 목표
이 프로젝트는 스피드옥션 경매 물건이 정비구역 안에 있는지 판정하고, **구역의 재개발 사업 단계로 입주권 가능 여부(A/B/C/제외)** 를 가른다
(`stage.py` 상단 docstring, README 4-1절). 단계 자료는 `data/zone_stage.csv`에 모인다.

- 지금 들어 있는 자료: 서울시 「정비사업 추진현황」 xlsx(`stage_seoul.py`로 가져옴). **분기 자료라 최대 5개월 뒤처지고(2026-06-30 기준)**
  분양신청 단계는 없어서 사업시행인가 후 120일이 지나면 B로 추정할 뿐이다.
- 이 작업의 목표: **대상 구의 구청장 고시·공고**에서 조합설립인가, 사업시행계획인가, 분양공고, 관리처분계획인가 등을 읽어
  같은 `zone_stage.csv`에 **더 최근 확인일의 행으로 덮어쓰기(추가)** 한다. 주 1회, 대상 구만.
- 대상 구는 `.env.normal`의 `DISTRICTS`(현재 광진구, 관악구). 구를 늘려도 코드 수정 없이 돌아가는 구조가 좋지만, 구청마다 게시판 형식이 달라
  **구별 어댑터로 나누고 지금은 광진구·관악구만 구현**한다.

## 2. 먼저 할 일 (정찰)
1. 아래 후보 출처를 PC 브라우저(Playwright 또는 직접)로 열어 어디서 고시를 가장 안정적으로 얻는지 정한다.
   - 각 구청 홈페이지 고시/공고 게시판 (gwanak.go.kr, gwangjin.go.kr)
   - 토지이음 고시정보 (eum.go.kr, 지방자치단체 고시를 통합 제공) — 한 곳에서 여러 구를 볼 수 있으면 우선 검토
   - 서울 도시계획포털 UPIS 고시 PDF (urban.seoul.go.kr/UpisArchive/...)
2. 각 출처의 `robots.txt`와 이용약관을 확인해 결과를 작업 메모에 남긴다. 자동 수집을 금지하면 그 출처는 쓰지 않고 사용자에게 알린다.
3. 목록 페이지와 상세 페이지의 **구조(제목, 고시번호, 고시일, 본문/첨부)** 를 파악하고, 파서 테스트용 샘플 HTML을 `tests/fixtures/notice/`에 저장한다
   (개인정보가 있으면 지우고 저장).

## 3. 만들 것
- `stage_notice.py` (이름은 바꿔도 됨): 출처별 어댑터가 고시 목록을 읽어 **고시 한 건 = 한 레코드**(제목, 고시번호, 고시일, 구, URL)로 돌려주고,
  공통 부분이 다음을 한다.
  1. 제목이 정비사업 관련인지 거른다(조합설립, 사업시행, 분양공고, 관리처분, 정비구역 지정, 이주, 착공, 준공 등).
  2. **단계는 `stage.normalize_stage(제목)`으로 해석**한다. None(해석 불가 또는 여러 단계가 섞임)이면 건너뛰고 로그에 남긴다.
  3. **구역 키워드는 `stage_seoul.keyword_of(구역명)`** 으로 만든다. 제목에서 구역명을 뽑는 규칙은 샘플을 보고 정한다.
  4. `data/zone_stage.csv`에 행을 병합한다. 열: `구역키워드, 자치구, 단계, 확인일, 출처, 사업유형, 비고`.
     - **확인일 = 고시일**(YYYY-MM-DD). 출처 = `관악구 고시 제2026-15호`처럼 고시번호까지.
     - 병합 키는 (자치구, 구역키워드, 출처). 서울시 자료 행(출처 `서울시 정비사업 추진현황`)은 **지우지 않는다.**
       `stage.lookup`이 같은 구역이면 확인일이 가장 늦은 행을 쓰므로 고시 행이 자동으로 이긴다.
     - 이미 더 최근 확인일의 행이 있으면 덮어쓰지 않는다. 사람이 적은 행(출처 `수동` 등)은 건드리지 않는다.
- 어댑터는 **한 구가 깨져도 다른 구는 계속**하고, 결과(추가/갱신/건너뜀/해석불가/실패)를 구별로 출력한다.
- `run_weekly.bat`에서 `sa_collect.py`(수집+매칭)보다 **먼저** 실행되도록 한 줄 추가한다. 로그는 `collect.log`.

## 4. 단계 해석 시 주의
- **변경 고시는 구분한다.** "사업시행계획인가(변경)", "관리처분계획 변경인가"는 단계는 같지만 최초 인가가 아니다. 단계는 해당 인가로 두고 비고에 "변경"을 적는다.
  (`stage_seoul.py`의 120일 분양신청 추정은 최초 사업시행인가일 기준이다.)
- **취소·폐지·해산·실효** 고시는 단계를 올리지 않는다. 건너뛰고 로그에 `확인 필요`로 남긴다.
- **분양공고**가 나오면 단계 `분양신청`(구간 B)이고, 이후 관리처분인가 고시가 나오면 `관리처분인가`(구간 C)로 넘어간다.
- 고시 본문에 **권리산정기준일**이 있으면 비고에 적는다(결과 엑셀 '확인할것'의 ①번을 실제 날짜로 채우는 데 쓴다).
- 법적 효력은 관보·구 고시 원문에 있다. 이 도구는 참고용이므로 `출처`에 항상 고시번호와 URL을 남긴다.

## 5. 지켜야 할 것
- 로그인하지 않는 **공개 페이지만** 읽는다. 로그인, CAPTCHA, 요청 서명, 응답 암호화를 우회하거나 해독하지 않는다.
- 호출 간격은 페이지 사이 3~6초, 구 사이 6~10초(`sa_collect.py`와 같은 수준). 주 1회, 대상 구만. 병렬 요청 금지.
- 막히거나 구조가 이해되지 않으면 **멈추고 사용자에게 보고**한다. 헤더·IP를 바꿔 가며 우회하지 않는다.
- 비밀 값은 `.env.credential`에만 둔다. 커밋하지 않는다(`.gitignore` 대상). 이 작업은 비밀 값이 필요 없다.
- 테스트 없이 끝내지 않는다. 저장한 샘플 HTML로 파서 테스트를 만들고, `pytest tests`가 전부 통과해야 한다(현재 63개 통과, 2개 xfail).

## 6. 완료 기준
1. `pytest tests` 통과 (새 테스트 포함).
2. 관악구·광진구 각각에서 실제 고시를 읽어 `data/zone_stage.csv`에 행이 병합된 것을 보여준다(건수와 예시 3건).
3. 병합 후 `python match_auctions.py --dry-run`이 아닌 실제 실행은 VWorld 키가 필요하다. 키가 없으면 `stage.attach`를 합성 데이터로 호출해
   고시 행이 서울시 행을 이기는지 확인한다.
4. `run_weekly.bat` 수정과 README 4-1절 설명 추가.
5. 커밋하고 `develop`에 푸시한다.
